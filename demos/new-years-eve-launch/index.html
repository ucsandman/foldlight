Every scheduled release starts exactly like this

Schedule the exact second your release goes live. Cutover flips traffic, DNS, or a feature flag at T-zero, synced across every region, and rolls back on its own if the error rate climbs.

Get early access See how the cutover works

One instant, every region

Cutover is a scheduler for the moment your release actually ships, not the moment you merge it. You pick the target and the second; Cutover's workers hold the change ready and release it everywhere at once.

40ms

Cross-region skew

NTP-disciplined workers in each region execute the cutover within 40ms of each other, so no user sees the old and new version at once.

90s

Rollback window

If your error rate crosses the threshold you set within the first 90 seconds, Cutover reverts the traffic split automatically, no page needed.

3

Cutover targets

DNS weight, load balancer traffic split, or a feature flag. Same schedule, same rollback logic, whichever layer you flip.

1

Schedule per release

One cutover, one clock. Cutover does not batch unrelated changes into the same window, so a rollback never takes back more than you shipped.
